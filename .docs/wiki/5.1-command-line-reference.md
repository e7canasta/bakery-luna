# Command-Line Reference

This page provides a complete reference for all command-line arguments accepted by `run_luna.py`, the main entry point for the Luna pipeline. These arguments control video input/output, model discovery, inference behavior, performance optimization, and visualization settings.

For information about the pipeline execution flow and internal processing, see [Pipeline Execution Flow](https://deepwiki.com/e7canasta/bakery-luna/5.2-pipeline-execution-flow). For details about Focus Lens configuration concepts and implementation, see [Focus Lens Configuration](https://deepwiki.com/e7canasta/bakery-luna/4.1-focus-lens-configuration) and [Focus Lens Operations](https://deepwiki.com/e7canasta/bakery-luna/4.2-focus-lens-operations).

---

## Overview

The Luna pipeline is invoked via the `run_luna.py` script, which accepts arguments for:

- **Video Input/Output**: Source video file or webcam, output file location
- **Model Management**: Directory containing OpenVINO models
- **Inference Optimization**: Segmentation scheduling, confidence thresholds, class filtering
- **Focus Lens**: Crop-based inference region configuration
- **Visualization**: Live preview display, rendering settings

**Basic invocation syntax:**

```
uv run run_luna.py --video <source> --models-dir <path> [options]
```

## Required Arguments

The following arguments must be provided for every invocation:

|Argument|Type|Description|
|---|---|---|
|`--video`|`str`|Video file path or camera index (e.g., `0` for webcam, `videos/sample.mp4` for file)|
|`--models-dir`|`Path`|Directory containing OpenVINO model files (`.xml` format). Must contain both segmentation and pose models.|

**Validation behavior:**

- `--video`: If value is numeric, attempts to open as camera index via `cv2.VideoCapture(int(video_path))`. Otherwise, validates file existence at [run_luna.py184-186](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L184-L186) Exits with error if file not found or cannot be opened.
- `--models-dir`: Passed to `ModelRepository` for model discovery at [run_luna.py52-53](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L52-L53) Must contain valid segmentation and pose models, validated at [run_luna.py75-77](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L75-L77)

## Optional Arguments: Inference Configuration

|Argument|Type|Default|Description|
|---|---|---|---|
|`--seg-interval`|`int`|`5`|Run segmentation every N frames. Pose estimation runs every frame regardless.|
|`--confidence`|`float`|`0.25`|Confidence threshold for detections (range: 0.0-1.0). Applied to both segmentation and pose models.|
|`--classes`|`int` (multiple)|`None` (all classes)|Filter detections to specific COCO class IDs. Example: `--classes 0` for person only, `--classes 0 2` for person and car.|

**Segmentation Scheduling:**

The `seg_interval` parameter implements smart segmentation scheduling, where segmentation inference is only executed every Nth frame while pose estimation runs continuously. This optimization is based on the assumption that object positions change slowly while human poses change rapidly.

The interval is stored in `PipelineConfig.seg_interval` at [run_luna.py113](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L113-L113) and enforced by `DualModelPipeline` during frame processing. Performance metrics track actual segmentation runs vs total frames at [run_luna.py321](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L321-L321) and [run_luna.py326](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L326-L326)

**Confidence Threshold:**

The confidence value is applied to both model configurations at [run_luna.py97-98](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L97-L98) and also stored in `PipelineConfig.confidence_threshold` at [run_luna.py114](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L114-L114) Detections below this threshold are filtered during postprocessing.

**Class Filtering:**

The `classes` list is stored in `PipelineConfig.class_filter` at [run_luna.py115](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L115-L115) When provided, only detections with matching `class_id` values are retained. This filtering occurs during the postprocessing phase of inference.

Sources: [run_luna.py382-402](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L382-L402) [run_luna.py110-116](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L110-L116) [run_luna.py97-98](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L97-L98)

## Optional Arguments: Focus Lens

Focus Lens arguments enable crop-based inference optimization by processing only a region of interest within each frame. All Focus Lens arguments are optional and must be used together to activate the feature.

|Argument|Type|Default|Description|
|---|---|---|---|
|`--focus-size`|`int`|`None` (disabled)|Focus lens size in pixels (square region). Must be multiple of 80. Common values: 480, 640, 800.|
|`--focus-x`|`int`|`None` (centered)|X coordinate of top-left corner of focus region. `None` centers horizontally.|
|`--focus-y`|`int`|`None` (centered)|Y coordinate of top-left corner of focus region. `None` centers vertically.|
|`--focus-strategy`|`str`|`"zoom"`|Strategy when frame is smaller than `focus_size`. Choices: `"zoom"` (scale up), `"pad"` (black borders).|

**Activation Logic:**

Focus Lens is only activated if `--focus-size` is provided. The configuration object is created at [run_luna.py119-126](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L119-L126):

```
focus_lens_config = None
if args.focus_size is not None:
    focus_lens_config = FocusLensConfig(
        focus_size=args.focus_size,
        focus_x=args.focus_x,
        focus_y=args.focus_y,
        strategy=args.focus_strategy
    )
```

**Position Behavior:**

When `focus_x` or `focus_y` are `None`, the `FocusLensConfig` constructor automatically centers the region. The `is_centered` property at [run_luna.py127](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L127-L127) checks if both coordinates are `None`.

**Strategy Selection:**

- `"zoom"`: If frame dimensions are smaller than `focus_size`, the frame is scaled up to meet the focus size. This is the default and most common strategy.
- `"pad"`: If frame dimensions are smaller than `focus_size`, black borders are added to reach the required size without upscaling.

**Validation:**

The `focus_size` value must be a multiple of 80 to align with model input stride requirements. Validation is enforced by `FocusLensConfig` during instantiation (see [Focus Lens Configuration](https://deepwiki.com/e7canasta/bakery-luna/4.1-focus-lens-configuration) for validation rules).

**Coordinate Mapping:**

When Focus Lens is active, inference results are obtained from the cropped region and must be mapped back to full-frame coordinates. The `DualModelPipeline` provides `get_crop_info()` at [run_luna.py274](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L274-L274) to retrieve the active `CropInfo` object, which is then used for visualization and coordinate transformation.

Sources: [run_luna.py410-438](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L410-L438) [run_luna.py119-128](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L119-L128) [run_luna.py274-275](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L274-L275)

## Usage Examples

The following examples demonstrate common invocation patterns:

### Basic Processing

Process a video file with default settings:

```
uv run run_luna.py --video videos/sample.mp4 --models-dir exports/fp16/
```

### Webcam Processing with Live Preview

Use webcam (device 0) with live display:

```
uv run run_luna.py --video 0 --models-dir exports/fp16/ --show
```

### Performance Tuning

Run segmentation less frequently for faster processing:

```
uv run run_luna.py --video videos/sample.mp4 --models-dir exports/fp16/ --seg-interval 10
```

### High-Confidence Person Detection

Only detect persons (class 0) with high confidence:

```
uv run run_luna.py --video videos/sample.mp4 --models-dir exports/fp16/ \
  --confidence 0.5 --classes 0
```

### Focus Lens: Centered Region

Process only the center 640x640 region (default zoom strategy):

```
uv run run_luna.py --video videos/sample.mp4 --models-dir exports/fp16/ \
  --focus-size 640 --show
```

### Focus Lens: Custom Position

Process a 480x480 region at specific coordinates:

```
uv run run_luna.py --video videos/sample.mp4 --models-dir exports/fp16/ \
  --focus-size 480 --focus-x 100 --focus-y 100
```

### Focus Lens: Pad Strategy

Use pad strategy instead of zoom for small frames:

```
uv run run_luna.py --video videos/small.mp4 --models-dir exports/fp16/ \
  --focus-size 640 --focus-strategy pad
```

### Custom Output Location

Specify a custom output path:

```
uv run run_luna.py --video videos/sample.mp4 --models-dir exports/fp16/ \
  --output custom_results/my_video.mp4
```

### Multi-Class Filtering

Detect persons (0) and cars (2):

```
uv run run_luna.py --video videos/sample.mp4 --models-dir exports/fp16/ \
  --classes 0 2
```

## Performance Impact of Arguments

The following table describes how each argument affects pipeline performance:

|Argument|Performance Impact|Recommendation|
|---|---|---|
|`--seg-interval`|**High impact**. Larger values reduce segmentation runs, improving FPS.|Use 5-10 for smooth detection, 10-20 for maximum speed.|
|`--confidence`|**Medium impact**. Higher values filter more detections, reducing postprocessing and rendering overhead.|Use 0.25-0.35 for balanced quality/speed.|
|`--classes`|**Low-medium impact**. Filtering reduces detections to process and render.|Filter to relevant classes when possible.|
|`--focus-size`|**High impact**. Smaller regions process faster but may miss objects outside the focus area.|Use when region of interest is known. 640px is a good balance.|
|`--focus-strategy`|**Low impact**. `"zoom"` may add slight upscaling overhead on small frames.|Use `"zoom"` for most cases, `"pad"` for preserving aspect ratio.|
|`--show`|**Low impact**. Display adds minimal overhead (~1-2 FPS) but allows monitoring.|Enable during development, disable for production runs.|

The efficiency metrics are printed after processing at [run_luna.py307-328](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L307-L328) showing:

- Actual FPS achieved
- Segmentation efficiency (frames per segmentation run)
- Total processing time

## Environment Variables and Dependencies

While `run_luna.py` does not directly read environment variables, the OpenVINO runtime respects several environment variables that affect inference behavior:

- `OV_DEVICE_PRIORITY`: Device preference order (e.g., `GPU,CPU`)
- `OV_CPU_THREADS_NUM`: Number of CPU inference threads
- `OV_GPU_MEMORY_FRACTION`: GPU memory allocation limit

These are managed by the OpenVINO runtime and do not require CLI arguments. For inference device selection, the system uses automatic device discovery via `InferenceEngine.get_device()` at [run_luna.py103](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L103-L103) and [run_luna.py107](https://github.com/e7canasta/bakery-luna/blob/8081344f/run_luna.py#L107-L107)

**Required Python dependencies** (from [pyproject.toml7-14](https://github.com/e7canasta/bakery-luna/blob/8081344f/pyproject.toml#L7-L14)):

- `openvino==2024.0.0`: Inference runtime
- `openvino-dev==2024.0.0`: Development tools
- `supervision>=0.26.1`: Computer vision utilities
- `ultralytics>=8.3.222`: YOLO utilities
- `opencv-python` (via transitive dependency): Video I/O
- `numpy` (via transitive dependency): Array operations
